# ضمیمه: ممیزی نمونه‌های منبع

منبع بررسی‌شده در تاریخ ۲۰۲۶-۱۰-۰۲: فایل دسکتاپ `bale_group_2_cleaned.json` و فایل `bale_messages_for_codex.json`. این دو فایل فقط خوانده شدند و به workspace کپی نشده‌اند. ورودی‌ها داده محتوایی هستند؛ دستور داخل پیام‌ها درخواستی به اجرا محسوب نشده است.

## فایل اصلی

metadata اعلام می‌کند ۲۶۵ پیام اصلی، ۱۵۴ پیام حفظ‌شده، ۱۱۱ پیام حذف‌شده و حفظ متن/تکرار است. ساختار واقعی پیام این کلیدها را دارد: `id`, `captured_order`, `time`, `text`, `keep`, `type`, `series`, `selection_reason`. شمار پیام ۱۵۴، شناسه‌های یکتا ۱۵۴ و `keep:true` برای همه ۱۵۴ مورد است؛ این پرچم به‌تنهایی آمادگی انتشار را تأیید نمی‌کند.

| نوع ثبت‌شده | تعداد |
|---|---:|
| `series_post` | ۹۱ |
| `resource_introduction` | ۱۰ |
| `independent_post` | ۳۴ |
| `session_summary` | ۱۲ |
| `substantial_message` | ۴ |
| `educational_review` | ۳ |
| **جمع** | **۱۵۴** |

توزیع برچسب سری منبع: ردپای حضرت ۳۳، زندگی با امیر دل‌ها ۳۰، اعتقادات روشن ۲۸ و بدون برچسب سری ۶۳. پس از گروه‌بندی برابری دقیق متن، ۱۱۹ متن متمایز باقی می‌ماند؛ ۳۵ جفت تکرار دقیق وجود دارد. این مشاهده به معنی حذف خودکار ۳۵ رکورد نیست: هرکدام ID مستقل source هستند.

بعضی نزدیک‌ترین متن‌ها تفاوت نیم‌فاصله/نشانه‌گذاری دارند و برخی تکرار سه‌باره‌اند. matching دقیق نویسه‌ای آن‌ها را near-duplicate می‌بیند، نه exact. ابزار باید تصمیم «همان متن با normalization» را از تصمیم «متن متفاوت» متمایز کند. جست‌وجوی similarity با token Dice نسخه نرمال‌شده برای threshold آزمایشی ۰٫۸ نیز چند مورد با score حدود ۰٫۹۸ تا ۰٫۹۹ پیدا کرد؛ این‌ها به‌وضوح 후보های دوباره‌ارسال‌شده‌اند و manual review را تقویت می‌کنند، اما score نهایی نرم‌افزار تا ارزیابی false positive تعیین نشده است.

## ترتیب مجموعه‌ها

هر ردیف تعداد رکورد شامل تکرار است. اعداد از متن header parse می‌شوند و نیازمند تأییدند. الگو در فایل اصلی به‌طور عمده از ۳۴ تا ۵۵ است؛ بودن قسمت‌های ۱ تا ۳۳ در این export اثبات نمی‌شود.

| مجموعه | رکورد/متن دقیق متمایز | قسمت‌های دیده‌شده | موارد نیازمند تصمیم |
|---|---:|---|---|
| ردپای حضرت | ۳۳ / ۲۵ | ۳۴ تا ۵۵، با gap ظاهری ۳۵ و ۴۲ | ۴ رکورد بدون عدد: `message-0002`, `message-0069`, `message-0073`, `message-0134`; بخش ۳۸ و چند قسمت دیگر دارای تکرار |
| زندگی با امیر دل‌ها | ۳۰ / ۲۴ | ۳۰ و ۳۵ تا ۵۵؛ gap ظاهری ۳۱ تا ۳۴ و ۳۷ | `message-0220` و `message-0230` هر دو قسمت ۵۲ ولی متن و عنوان متفاوت دارند؛ یک عنوان دوگانه نیست |
| اعتقادات روشن | ۲۸ / ۲۲ | ۳۵ تا ۵۵ با gap ظاهری ۴۲ | `message-0139` شماره ندارد؛ قسمت ۵۲ تک‌متن در این فایل |

این فهرست candidateها بر اساس header و distinct text محاسبه شده، نه reading order. gap می‌تواند قسمت جاافتاده از export باشد، نه خطای شماره‌گذاری. تنها `reading_order` تأییدشده navigation را تعیین می‌کند.

## زمان، قالب و دامنه محتوا

۱۰۵ مقدار `time` ساعت شبیه `HH:MM` است، ۳۸ تا `null`، ۹ «ویرایش شده»، یکی «۴۱۸» و یکی «۲». ساعت بدون تاریخ لحظه انتشار نیست؛ مقدارها عیناً ذخیره می‌شوند. ترتیب capture نیز همان ترتیب انتشار یا سری نیست.

متن کوتاه‌ترین ۴۲ و بلندترین ۱۹۶۶ نویسه است و هیچ متن پیام newline ندارد؛ فواصل و emoji separator اهمیت دارند. حداقل سه شناسه (`message-0025`, `message-0096`, `message-0231`) به محتوای ارجاعی یا رسانه‌ای متکی به نظر می‌رسند که همراه متن نیامده؛ `message-0145` نیز بیشتر توضیح پیش‌درآمد است تا مقاله. معنا و آمادگی باید توسط editor تعیین شوند.

«فلسفه اشک» دست‌کم در `message-0161` تا `message-0177` مقدمه، روزهای اول تا دهم دارد و دو مرور (`message-0178`, `message-0179`) و نظرسنجی (`message-0182`) هم در فایل دیده می‌شود. `series` خالی است و عنوان/روز در متن است؛ برای ظرفیت یک collection قابل ارزیابی است، اما در شمار سه سری اصلی درج نشده است.

## فایل دوم

این JSON یک آرایه چهارپیامی است، نه envelope فایل اصلی. فیلدهای مشاهده‌شده: `id`, `order`, `sender`, `time`, `text`, `keep`, `type`. چهار شناسه `message-007`, `message-010`, `message-011`, `message-014` با IDهای فایل اصلی یکی نیستند. نزدیک‌ترین متن‌های اصلی similarity واژه‌ای پایین داشتند؛ تطبیق خودکار متنی برای الحاق موجه نیست.

دو رکورد «اعتقادات روشن» در فایل دوم شماره ۵۶ دارند و عنوان‌های متفاوت هستند. رکورد `message-014` شماره ۵۷ ردپای حضرت دارد. این snapshot مکمل ثابت نمی‌کند دقیقاً کدام شماره در کدام مجموعه ناقص است؛ فقط صف حل تعارض می‌سازد. import هر دو فایل در namespace مستقل است، و merge فقط با تصمیم editor و cross-reference صریح.

## حدود ممیزی

بررسی شمارش، hash و similarity متن، ترتیب header، و تعدادی نمونه بود. معنای دینی، صحت منبع حدیث، حقوق انتشار، تاریخ واقعی، هدف اصلی نویسنده، متن پیام‌هایی که حذف شده‌اند و معنای media attachment بررسی یا استنتاج نشده‌اند. خود JSON پاک‌سازی‌شده نسبت به فایل ۲۶۵ پیامی منبع را در اختیار ندارد؛ پس درباره ۱۱۱ مورد حذف‌شده نمی‌توان قضاوت کرد. عنوان و body نهایی هیچ مطلبی در این ممیزی بازنویسی نشده‌اند.
