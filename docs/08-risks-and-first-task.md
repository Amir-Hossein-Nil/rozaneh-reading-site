# ریسک‌ها، تصمیم‌های باز و اولین کار

## ریسک و راه کاهش

| ریسک | پیامد | کاهش و نقطه تصمیم |
|---|---|---|
| دسترسی hosting به Node SSR و reverse proxy قابل اتکا نامعلوم است | تقسیم Astro/Next ممکن است با دامنه یا cookie ناسازگار شود | فاز صفر مسیر واقعی دو build، `/app`، asset و callback را staging-probe می‌کند؛ در نبود پشتیبانی به یک برنامه Next کاهش می‌یابد |
| session cookie میان دو app | auth ظاهراً در یکی کار می‌کند و در دیگری کهنه می‌ماند | یک origin؛ نشست فقط Next؛ `/app/api/session`؛ redirect کامل؛ آزمون refresh واقعی و عدم cache |
| انتشار و cache | مطلب حذف‌شده در HTML، search یا CDN می‌ماند | آغاز بدون cache HTML؛ همه مسیرهای مرتبط فقط projection؛ purge پیچیده به فاز جدا موکول می‌شود |
| پالایش نشدن ۱۵۴ پیام | مطلب ناتمام، رسانه‌محور یا تکراری عمومی می‌شود | queue، حفظ اصل، double approval policy و هیچ auto-publish |
| محتوای دینی شامل ادعا/نقل نامطمئن | خطای انتساب به سایت منتقل می‌شود | حفظ عین متن؛ هیچ fact-check بی‌درخواست؛ editor مسئول مجوز، انتساب و انتخاب انتشار؛ گزارش اصلاح بیرونی جداگانه |
| حریم خصوصی progress | حساب مدیر داده مطالعه کاربران را می‌بیند | RLS و منع دسترسی مدیر به history؛ آزمون خصمانه، retention/delete مشخص |
| سایز scope و دو framework | تأخیر، duplication و regression | vertical slice کوچک؛ Astro/Next مالکیت مسیر روشن؛ defer features اجتماعی غیرضروری |
| rubric Gemini موجود نیست | ممکن است شواهد ارزیابی نامرتبط باشند | setup قابل تکرار، معماری مستند، تست قابل نمایش و artifact همان build؛ درخواست rubric در زمان دریافت |

## تصمیم‌هایی که نیاز به صاحب پروژه دارند

این ابهام‌ها واقعاً می‌توانند معماری/حقوق/انتشار را تغییر دهند. پاسخ فعلی با پیش‌فرض ارائه شده تا طرح قابل ارزیابی باشد.

1. **آیا وجود هر دو Astro و Next شرط الزام‌آور ارزیابی است؟** پیش‌فرض: بله؛ اگر خیر، Next واحد هزینه و استقرار را کم می‌کند.
2. **حساب hosting، دامنه و منطقه مجاز داده کجاست و چه محدودیت Node دارد؟** پیش‌فرض: میزبانی Node و یک origin قابل route، منطقه با تأیید مالک انتخاب می‌شود. انتخاب ناحیه Supabase، محل نگهداری داده و خرید پلن تا مشخص‌شدن مالک پروژه بسته است.
3. **آیا برای تمام متن‌های JSON و تصاویر حقوق انتشار عمومی وجود دارد؟ چه کسی تأیید می‌کند؟** پیش‌فرض: هیچ‌کدام پیش از approval منتشر نمی‌شوند؛ مسئول تحریریه پیش از هر batch اعلام می‌شود.
4. **حساب کاربری نسخه اول ضروری است؟** پیش‌فرض: بله، چون history/private cross-device و دیدگاه جزو درخواست‌اند؛ می‌توان دیدگاه را به مرحله بعد موکول کرد، ولی Auth یکپارچه با داشبورد می‌ماند.
5. **آیا اطلاع از تعداد بازدید برای مدیر لازم است یا فقط تکمیل و پیشرفت؟** پیش‌فرض: شمار aggregate روزانه مطلب/شروع/تکمیل بدون profile رفتار.
6. **محدودیت rubric یا قالب تحویل Gemini معلوم شده؟** پیش‌فرض: خیر؛ تست‌ها و README ساده، هیچ optimizer مخصوص مدل.

تنها سؤال‌های ۱ تا ۳ برای شروع زیرساخت لازم‌اند. سؤال‌های ۴ تا ۶ را می‌توان پس از vertical slice قطعی کرد. پاسخ‌ندادن به سؤال اختیاری مانع مستندسازی یا طرح نیست.

## اولین کار پس از تأیید طرح

**یک vertical slice end-to-end، پیش از ورود داده واقعی:** یک monorepo کوچک با `apps/reader` و `apps/console`، workspace و lockfile؛ دو migration حداقلی: demo collection و published post + RLS، و bookmark با ownership؛ seed ساختگی یک مجموعه و دو مطلب؛ Astro صفحه collection/post RTL با یک token set؛ Next زیر `/app` ثبت‌نام/ورود/callback و route session؛ gateway محلی/preview با یک origin؛ نشانک عضو؛ آزمون مستقیم DB برای تفکیک دو حساب و یک Playwright flow برای خانه → مطلب → نشانک → ورود به `/app` → بازگشت به خواننده → خروج.

**خارجی که برای این کار باید بسته شود:** مسیر gateway و SSR در hosting در دسترس، یک پروژه staging Supabase در منطقه مجاز، ایمیل callback قابل استفاده و credentialهای staging در secret store. اگر مالک هنوز سرویس انتخاب نکرده، ابتدا نسخه محلی Supabase CLI و stub gateway ساخته می‌شود؛ داده واقعی یا secret production لازم نیست.

**معیار تحویل اولین کار:** در مرورگر واقعی یک session پس از رفت‌وآمد میان Astro و Next زنده می‌ماند؛ دو کاربر نشانک هم را نمی‌خوانند؛ private data در cache عمومی نیست؛ صفحه موبایل RTL و keyboard reachable است؛ از DB خالی build و setup مستند قابل تکرار است. فقط پس از این نتیجه معماری دوچارچوبی ارزش ادامه دارد. این همان فاز یک roadmap است و شروع آن مستلزم تأیید کاربر بر طرح و تصمیم hosting/auth است؛ این turn در این نقطه متوقف می‌شود و application code نمی‌سازد.
