# ورود داده و تحریریه

## مبنای واقعی

فایل اصلی envelope شامل `messages` و metadata دارد؛ فایل دوم آرایه است و فیلد `order` به‌جای `captured_order`، همچنین `sender` و `keep/type` تهی دارد. شمارش دقیق و استثناها در [ضمیمه داده](09-source-audit.md) آمده‌اند. هر دو خوانده شدند؛ فعلاً فایل اصلی مبنای آرشیو و فایل دوم مجموعه ورودی مکملِ نیازمند بررسی است، نه جایگزین آن.

متن‌ها فاقد newline واقعی‌اند؛ ایموجی‌ها و جداکننده‌ها اغلب تنها نشانه بخش‌بندی هستند. هیچ ساختار مقاله یا عنوان مستقل از پیش موجود فرض نمی‌شود. `keep=true` فقط یعنی در export نگه داشته شده، نه تأیید انتشار.

## قرارداد حفظ منبع

فایل اصلی به‌صورت bytes در فضای خصوصی بایگانی و SHA-256 آن ثبت می‌شود. هر raw JSON و مقدار `original_text` دقیقاً نگه داشته می‌شود. نام فایل برای هویت dataset کافی نیست؛ namespace پایدار در شروع import انتخاب می‌شود. شناسه `message-007` با `message-0007` برابر فرض نمی‌شود؛ حتی اگر مقدار عددی مشابه باشد.

اجرای دوباره همان فایل به همان run/result اشاره می‌کند. فایل تغییریافته با همان external ID یک source version جدید می‌سازد و نسخه قبلی را دست‌نخورده نگه می‌دارد؛ تصمیم تحریریه قبلی بازنویسی نمی‌شود. متن یکسان با ID متفاوت، دو source record باقی می‌ماند که می‌توانند به یک post اشاره کنند. hash متن معیار یکتایی source record نیست.

`captured_order` و `order` فقط provenance هستند. `raw_time` رشته خام باقی می‌ماند؛ `source_published_at` برای داده فعلی null است. حتی اشاره به سال، نوروز یا اربعین در متن، تاریخ انتشار محسوب نمی‌شود. تاریخ انتشار وب‌سایت هنگام انتشار واقعی جدا ثبت و با همان عنوان نمایش داده می‌شود.

## مراحل ورود

1. **پیش‌بررسی:** مجوز editor/admin، محدودیت فایل پیشنهادی ۱۰MB، UTF-8 و JSON معتبر، شناسایی schema، تعداد و کلیدها. payload اجرای کد نیست؛ متن‌ها escape می‌شوند. رکورد خراب به quarantine می‌رود و در گزارش شمارش می‌شود؛ نادیده‌گرفتن بی‌صدا ممنوع.
2. **Dry-run:** آمار، hash، رکوردهای جدید/تغییریافته/قبلی، تکرار و flags بدون انتشار یا تغییر محتوای عمومی. ثبت یک import receipt و امکان دانلود گزارش.
3. **ثبت idempotent:** transaction یا batchهای قابل resume با unique constraints؛ قطع فرایند و اجرای مجدد رکورد اضافه نمی‌سازد. parser version و log خطا ثبت می‌شوند.
4. **تشخیص تکرار:** SHA-256 روی UTF-8 متن دقیق، سپس مقایسه equality برای تأیید. near-duplicate روی نسخه مشتق‌شده نرمال‌شده با token similarity و شباهت عنوان؛ آستانه فقط صف بازبینی می‌سازد. شباهت معنایی احتمالی به معنی یکسان‌بودن نیست.
5. **استخراج پیشنهادی:** نام مجموعه با alias؛ عنوان از بخش مناسب header؛ `بخش/قسمت/روز` و ارقام فارسی/عربی/لاتین و عددهای نوشتاری؛ confidence و قطعه شاهد برای هر فیلد. پاسخ نامطمئن null است. metadata پیشنهادی بدون تأیید عمومی نمی‌شود.
6. **صف تحریریه:** دو متن کنار هم با diff نویسه‌ای و نمایش کاراکترهای نامرئی؛ تصمیم «یک مطلب»، «دو مطلب»، «نیازمند اطلاعات» یا «نامناسب برای انتشار مستقل». canonical را مدیر انتخاب می‌کند، نه capture order یا ساعت.
7. **ترتیب:** شماره استخراج‌شده، شماره تأییدشده و reading order جدا هستند. gap و تعارض باید دیده شوند. جای خالی با متن یا شماره ساختگی پر نمی‌شود؛ استثنای تأییدشده با دلیل یا انتقال به مقدمه/پیوست امکان‌پذیر است.
8. **آماده‌سازی نمایش:** بلوک‌بندی پیشنهادی فقط در نقاط انتخاب‌شده؛ paragraph، heading، quote و list با schema مجاز. leafهای متن به sliceهای اصل اشاره می‌کنند و الحاق آن‌ها باید دقیقاً original text را بازتولید کند. افزودن عنوان مستقل metadata مجاز است؛ بازنویسی، حذف ایموجی یا اصلاح خودکار غلط املایی مجاز نیست. خطاهای موجود در نقل‌ها بدون درخواست جدید اصلاح نمی‌شوند.
9. **بازبینی و انتشار:** مدیر اصل، پیش‌نمایش، نوع، موضوع، ترتیب، حقوق استفاده و flags را بررسی می‌کند. نیاز به مدرک یا رسانه گمشده publication blocker است. accepted → draft؛ انتشار تنها با اقدام جدا و ثبت actor/revision انجام می‌شود.

ایجاد محتوای جدید در مدیریت یک متن authored و نسخه‌بندی‌شده دارد. ویرایش مطالب واردشده در نسخه اول محدود به metadata و formatting حفظ‌کننده متن است؛ قابلیت عمومی «ویرایش» نباید این قید را نقض کند. هر تغییر محتوایی آینده نیازمند تصمیم صریح خارج از این مهاجرت است و اصل منبع همچنان immutable می‌ماند.

## موارد واقعی نیازمند تصمیم

- دو متن متفاوت «نحوه‌ی پرسش‌گری» و «برنده‌ای یا پیروز» در `message-0220` و `message-0230` هر دو شماره ۵۲ زندگی با امیردل‌ها دارند؛ این تکرار دقیق نیست.
- دو متن متفاوت فایل مکمل در `message-010` و `message-011` هر دو شماره ۵۶ اعتقادات روشن دارند؛ هیچ‌کدام خودکار ۵۷ نمی‌شود.
- `message-0069`/`message-0134` و `message-0139` header بدون عدد دارند؛ جایگاهشان از فاصله میان قسمت‌ها حدس زده و ثبت نمی‌شود.
- `message-0025`/`message-0096` صرفاً معرفی کوتاه یک نجوا و `message-0231` اشاره به محتوای بالا دارد؛ خود export رسانه لازم را ارائه نمی‌کند.
- «فلسفه اشک» در `series` برچسب نخورده، ولی مقدمه، روزهای اول تا دهم و مرور/نظرسنجی در متن دیده می‌شود؛ طبقه‌بندی فعلی حقیقت نهایی نیست.

## معیار پایان مهاجرت

تمام ۱۵۴+۴ رکورد دارای provenance و وضعیت بررسی‌اند؛ تعداد postهای نهایی پیشاپیش تعیین نمی‌شود. هر رکورد یا به مطلب پیوند دارد یا با دلیل در حالت بررسی/کنارگذاشته‌شده باقی است. اجرای مجدد هیچ source، draft یا تصمیمی را تکثیر نمی‌کند. مقدار متن اصلی و hash فایل با منبع برابر است؛ هر مطلب منتشرشده فقط یک نسخه عمومی و ترتیب تأییدشده دارد. هیچ سابقه زمانی ساخته نشده و هیچ مطلب مسدودشده به جست‌وجو یا sitemap راه نمی‌یابد.
